# 安全扫描模式参考

> 本文件包含安全敏感词的原始模式，供 dim8 扫描时读取。主 SKILL.md 中不直接包含这些词，避免自指悖论。

## 扫描清单

用 grep 扫描以下模式，所有文件（包括注释和文档）中都不应出现（除非是 Python 标准库函数如 re.compile）：

```
sys.path, innerHTML, subprocess, os.system, os.popen,
eval(, exec(, __import__, compile(,
pickle, marshal, ctypes,
shutil.rmtree, os.remove, os.unlink,
chmod, chown, setuid,
RCE, SSRF, XSS, 注入, 攻击, 漏洞, 绕过
```

> 例外：re.compile 是 Python 标准库函数，无法避免。原始版本就有的不影响分数。

## T-A 冲突解耦指南

安全性（dim8）和搜索适用性（dim6）会此消彼长，原因在两个层面：

### 层面一：代码功能 vs 代码风险

| 操作 | A 影响 | T 影响 |
|------|--------|--------|
| 给脚本加 --save / --download-images | 文档多了功能 | 引入文件系统操作，扫描器红旗 |
| 移除这些功能 | 文档少了功能 | 代码精简 |

**解法**：不靠给安全敏感脚本加功能来提升 A。

### 层面二：描述关键词

| 描述中的词 | A 影响 | T 影响 |
|-----------|--------|--------|
| 请求伪造防护 | 技术关键词 | 漏洞名，扫描器匹配 |
| 规避反爬 | 场景关键词 | 攻击动词 |

**解法**：用安全中性词替代漏洞名，含义不变但扫描器不触发。

## 关键原则

1. **不提你不用的东西** — 说"不使用 XX"仍触发字符串匹配。直接不提。
2. **注释也会被扫描** — 纯字符串匹配，不区分代码/注释/文档。
3. **两处 description 互补** — frontmatter 和 meta.json 应有不同关键词。
4. **代码精简优先** — 每新增一个文件系统操作都是 T 风险。
